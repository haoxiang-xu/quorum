# Quorum

> **quorum** — 议事有效所需的最少出席者；在分布式系统中，则是达成决议所需的最小节点集。

一套 agent team 的 **宪法、议事程序与角色法典**。

多 agent 协作的失败模式，往往不是模型不够聪明，而是：**该到场的人没到场、证据没人验、决定没人记、出了错不知道是哪一步错的。** Quorum 用一套庭审制的程序回答这四个问题 —— 立案、传唤、质证、裁定、执行、验收、归档，每一步都有明确的角色与留痕。

## 几条核心设计

**人是唯一的裁决者。** `Chief Judge` 由人担任，一切裁决权归属于它；程序裁定可明示授权下放，未授权事项专属于人。同一人以 `Witness` 身份提供事实时，证言与裁决严格分离。

**方案先行。** 任何产生真实影响的 action，都必须以一份经裁定通过的、**可验收的**方案为依据。简化的是方案的形成过程，不是方案本身。

**传唤不靠猜。** 出庭名单由三层机制依次产生：所有权边界的机械匹配 → 认领期自请出庭 → 闭庭前的集合差检查。每捞回一名缺席者，就构成一条"该角色的边界声明写窄了"的信号 —— **边界随使用而收敛**。只有可查来源已经穷尽且裁定仍缺少本人特有事实时，才例外传唤 `Witness`；回答“不知道”也是有效答案，agent 不得代为补全。

**证据审查不由任何人裁量。** 触发条件被穷举：被质疑的证据、一次性观察、证言、以及 **裁定压在上面的承重证据**，命中即查，未命中即不查。没有"主持人有权要求审查"这种表述 —— 它读起来像保障，实际是把审查的有无系于一个无人复核的主观状态。

**质疑权归当事人，补强责任归举证方。** 任何出庭角色都可以质疑任一证据的真实性、来源或相关性；符合形式要件即 **强制触发** 审查。补强被质疑证据的责任归于 **提出该证据的一方** —— 这与"反驳观点的举证责任在异议方"是两种不同的责任，混用会让质疑权名存实亡。主持人 **不持有质证权**：裁判不质疑证据，当事人才质疑。

**承重证据在闭庭前复核，自证类不豁免。** 哪些算承重由编号机械导出，不由任何角色挑选。免检是对大批量证据的分流，而当一个结论压在它上面时，**验证成本低是复核它的理由，不是跳过它的理由** —— 何况一次庭审可长达数小时，早期取得的定位到闭庭时未必仍成立。庭外陈述（文档、注释、他人记忆）则只能证明"该陈述曾被作出"，不能证明其所述为真。

**发言不是自由聊天。** 每条发言都有动作、speaker、target、依据、不确定性与下一步，并通过稳定编号互相引用。角色使用各自的输出契约，`Speaker of the House` 在闭庭前显式汇总共识、分歧、已知缺口、候选方案、风险与强制回应事项。

**档案只有一个事实源。** 每个 case 使用人可读且可解析的 Markdown 档案；发言、证据、方案、裁定与验收各有唯一 canonical source，摘要只引用原始编号，不复制后独立演化。

**分歧是产出。** 评估维度之间不要求收敛，也不设收敛程序；分歧本身就是呈给裁决者的信息。

**成本分档。** 并非所有议案都值得走完整流程。Fast Track / Express / Full 依 **客观属性** 分档，不依事情的大小或重要性 —— 大小是主观判断，而判断本身即是成本。

**charter 不复述宪章。** 每个 agent 的 prompt 只写它独有的对象、已验证的方法、已知的纠错。一份全是别处已有内容的 charter，信噪比为零 —— 写死的规则不需要持有者。

## 状态

设计阶段。宪章已覆盖 Witness、庭审发言协议与庭审档案格式，尚无 department 或运行时落地。

已知的待补条款，最要紧的一条是：**没有任何角色产出"我倾向批/驳，且这么改最可能错在哪"** —— `Speaker of the House` 中立汇总且不持有记忆，`Expert` 与 `Dimension Owner` 各自只在本领域或本维度内结论，裁决者因而需自行读完全部庭审产出。
