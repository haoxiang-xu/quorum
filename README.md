# Quorum

> **quorum** — 议事有效所需的最少出席者；在分布式系统中，则是达成决议所需的最小节点集。

一套 agent team 的 **宪法、议事程序与角色法典**。

多 agent 协作的失败模式，往往不是模型不够聪明，而是：**该到场的人没到场、证据没人验、决定没人记、出了错不知道是哪一步错的。** Quorum 用一套庭审制的程序回答这四个问题 —— 立案、传唤、质证、裁定、执行、验收、归档，每一步都有明确的角色与留痕。

## 几条核心设计

**人是唯一的裁决者。** `Chief Judge` 由人担任，一切裁决权归属于它；程序裁定可明示授权下放，未授权事项专属于人。同一人以 `Witness` 身份提供事实时，证言与裁决严格分离。

**方案先行。** 任何产生真实影响的 action，都必须以一份经裁定通过的、**可验收的**方案为依据。简化的是方案的形成过程，不是方案本身。

**先判断是否需要立案。** 咨询、解释、状态查询与只读诊断不形成方案、不授权 action 时直接回答，不创建 case、roster 或证据流程。Quorum 只接管真正需要设计或裁定的事项。

**参与名单由人批准。** 所有权匹配、自请出庭与直接影响复核只产生候选请求；初始名单和后续每一个新增 agent 或 role instance，均须由 `Chief Judge` 明示批准。证据里顺带出现一个实体，不再自动召来它的 owner。

**相关性先于完整性。** `Speaker of the House` 只把可能改变 track、方案、owner 分工、验收、回滚或裁定的内容留在主流程。真实但无关、重复、范围外或尚未到时机的内容会被合并、移出或退回；同一规则覆盖 Fast、Express、Debate 与 Full。

**质疑权归当事人，补强责任归举证方。** 已获准出庭的角色可以质疑证据的真实性、来源或相关性；质疑须点名对象和决策影响。补强责任仍归提出证据的一方，但质疑不再自动制造逐条审查。

**只抽查会改变抉择的证据。** `Speaker of the House` 冻结最小、去重的决策证据集；`Evidence Examiner` 默认只随机抽查 16%，给出可复现的批次置信度报告。首批完成后自动核验停止，只有 `Chief Judge` 能决定再抽一批、点名定向核验、返修或直接裁定。

**发言不是自由聊天。** 每条实体发言必须指向一个具体抉择，并说明它会改变什么。首次完整审查后冻结有限阻塞清单，不再新增 material 线程；辩论不设固定轮数，但只有新证据或方案变化让开放条件严格减少时才续轮，稳定分歧直接交给人裁定。

**档案只有一个事实源。** 每个 case 使用人可读且可解析的 Markdown 档案；发言、证据、方案、裁定与验收各有唯一 canonical source，摘要只引用原始编号，不复制后独立演化。

**分歧是产出。** 评估维度之间不要求收敛，也不设收敛程序；分歧本身就是呈给裁决者的信息。

**成本分档。** Fast Track 免庭直行；Express 协调一份路径已定的方案；Debate 由主 owner 起草集成方案、其他 owner 补全并 ACK 或反驳；Full 保留原有准入条件与完整九步。四档共享同一套收敛、抽样和增员审批规则。

**charter 不复述宪章。** 每个 agent 的 prompt 只写它独有的对象、已验证的方法、已知的纠错。一份全是别处已有内容的 charter，信噪比为零 —— 写死的规则不需要持有者。

## 状态

设计阶段。宪章已覆盖 Witness、四档 Track、辩论庭、庭审发言协议与庭审档案格式，尚无 department 或运行时落地。Debate 由主 owner 提交集成方案、当前推荐与最大失败点；`Speaker of the House` 继续保持程序中立。
