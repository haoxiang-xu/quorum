# Quorum

> **quorum** — 议事有效所需的最少出席者；在分布式系统中，则是达成决议所需的最小节点集。

一套 agent team 的 **宪法、议事程序与角色法典**。

多 agent 协作的失败模式，往往不是模型不够聪明，而是：**该到场的人没到场、证据没人验、决定没人记、出了错不知道是哪一步错的。** Quorum 用一套庭审制的程序回答这四个问题 —— 立案、传唤、质证、裁定、执行、验收、归档，每一步都有明确的角色与留痕。

## 几条核心设计

**人是唯一的裁决者。** `Chief Judge` 由人担任，一切裁决权归属于它；程序裁定可明示授权下放，未授权事项专属于人。

**方案先行。** 任何产生真实影响的 action，都必须以一份经裁定通过的、**可验收的**方案为依据。简化的是方案的形成过程，不是方案本身。

**传唤不靠猜。** 出庭名单由三层机制依次产生：所有权边界的机械匹配 → 认领期自请出庭 → 闭庭前的集合差检查。每捞回一名缺席者，就构成一条"该角色的边界声明写窄了"的信号 —— **边界随使用而收敛**。

**分歧是产出。** 评估维度之间不要求收敛，也不设收敛程序；分歧本身就是呈给裁决者的信息。

**成本分档。** 并非所有议案都值得走完整流程。Fast Track / Express / Full 依 **客观属性** 分档，不依事情的大小或重要性 —— 大小是主观判断，而判断本身即是成本。

**charter 不复述宪章。** 每个 agent 的 prompt 只写它独有的对象、已验证的方法、已知的纠错。复述通用规则会把信噪比压低到零，而信噪比是本体系明确设立的评估维度之一 —— 这条约束可被直接取证。
